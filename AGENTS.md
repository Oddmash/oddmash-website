# Oddmash organization website

Follow Oddmash organization agreements and shared product, brand, accessibility, web delivery, privacy, QA and Git workflow guidance. The public static website is deployed through GitHub Pages. Keep preview builds noindex; the Pages build uses the approved public origin. No tracking or unpublished project material in the deployed artifact. Position Oddmash as Developer Experience Lab. Lead with public products and developer problems, not the maintainer or agents. Verify browser-language entry, explicit locale switching, project links, multilingual editorial wrapping, documentation copy feedback, responsive layout and keyboard access before release.

Follow the [Oddmash review follow-up guidance](https://github.com/Oddmash/.github/blob/main/docs/AI-CODE-REVIEW.md#following-up-on-review-findings) when addressing review comments, including recording non-adoption or deferral and the final thread disposition.

## Agent contribution attribution

Follow the [Oddmash agent attribution convention](https://github.com/Oddmash/.github/blob/main/AGENTS.md#agent-contribution-attribution). When a commit materially incorporates a verified finding or recommendation from Reviewer, Impact, Triage, QA, Release, Docs, or Architect, append the canonical `Co-authored-by` trailer for each actual contributing GitHub account. Deduplicate trailers, preserve human authorship and record the source role or discussion for shared identities. Do not credit unused advice or rewrite published history.

## Branch workflow

This organization website is a main-only repository. Create focused topic branches from `main` and target `main` directly. Do not create or use `develop`. Keep issue linkage, required CI, review, normal merge commits, and GitHub Pages deployment from `main`.

## Website experience

Keep product and workflow-resource cards consistently aligned with logical-end actions, generous standalone hit targets and native independently focusable links. Link to verified destinations only; omit unavailable platform links. Product detail pages explain the problem, operation, expected outcome and fit before linking to the actual product homepage. Select the first supported browser language only at the initial home route, preserve explicit localized routes and manual selections, and use the matching localized product capture and social metadata. Keep documentation copy controls; do not add redundant global share controls.

Home leads with one compact gallery of public projects, then presents the shared development method, agent role artwork and an illustrative workflow. Keep document scrolling natural. Use a compact cinematic workflow player that automatically plays only when visible and motion is permitted, loops continuously while visible, pauses during pointer hover or keyboard focus, supports a compact persistent keyboard-operable pause/resume control and touch pause/resume, keeps all visible text fully legible during transitions and pauses, and preserves every stage with ordinary content under reduced-motion or no-script conditions. Use role-specific hover/focus gestures with the unmodified icon at rest. Animate outside the badge face where possible; keep the underlying role symbol legible and avoid motion on reduced-motion preferences. Keep the detailed agent and skills documentation on dedicated localized routes, with only the summary and character artwork on the home page. Public artwork and verified public Oddmash Skills and Oddmash Agents repository links may be included, but never publish private repository links, sensitive runtime details, or unpublished plans. Agents advise and review; maintainers and applicable CI own release decisions and publishing. The language selector must retain its route and provide a no-script fallback. Apply the verified published Juliya engine to all eligible supported-language editorial prose, including documentation, nested inline text and active workflow stages. Verify rendering at narrow and wide widths; preserve native wrapping for unsupported languages and interactive controls. Do not consume unreleased packages. Present skill usage, behavior and expected results in localized practical guides. Provide a compact workflow-based catalog, Markdown copy and safe installation instructions. Keep versioned source available for copying and source verification, with required license notices retained in distributed assets.
